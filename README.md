# Booking API — Система бронирования переговорных комнат в коворкинге

REST API для бронирования переговорных комнат в коворкинге.  
Пользователи видят список комнат и могут забронировать их на нужное время. Система автоматически проверяет пересечение интервалов.  
Администраторы управляют списком комнат и могут отменять любые бронирования.

**Аналоги в реальной жизни**: внутренние системы бронирования в офисах, часть функционала Calendly / Airbnb / Booking.com.

## Текущий статус проекта

**Этап 3 завершён** (основная бизнес-логика)

- Полная авторизация через JWT (регистрация, вход, выход)
- Роли пользователей: `user` (обычный) и `admin`
- CRUD для ресурсов (переговорные комнаты) — только админ может создавать, редактировать и удалять
- Создание бронирования с проверкой пересечения времени (409 Conflict при занятости)
- Отмена бронирования (только своё или любое — для админа)
- Просмотр списка своих бронирований
- Защита маршрутов по авторизации и ролям

## Стек технологий

## Установка и запуск (для проверяющего)

1. Клонировать репозиторий

   git clone https://github.com/Ezhevskiy/practice-backend-2026.git

Установить зависимости
Bash

Скопировать .env и сгенерировать ключ приложения
Bash
copy .env.example .env
php artisan key:generate

Сгенерировать секретный ключ JWT (обязательно!)
Bash
php artisan jwt:secret

Настроить подключение к базе данных в .env
Пример для XAMPP:textDB_CONNECTION=mysql
DB_HOST=127.0.0.1

DB_USERNAME=root
DB_PASSWORD=

Создать базу данных booking_api (через phpMyAdmin или консоль MySQL)

Выполнить миграции и добавить тестового админа

Bash
php artisan migrate

php artisan db:seed --class=AdminSeeder

Запустить сервер
Bash
php artisan serve

API будет доступно по адресу: http://127.0.0.1:8000/api

Основные эндпоинты (на момент Этапа 3)

Метод   Путь            Описание                             Доступ      Токен

POST    /api/login      Вход и получение JWT-токена           Гость        Нет

GET/    api/me          Информация о текущем             Авторизованный    Да
                          пользователе

DELETE  /api/bookings/{id}   Отменить бронирование        Своё или админ   Да

email: admin@example.com

Обычный пользователь — регистрируйте через /api/register

Демонстрация (Postman)
Коллекция запросов доступна в репозитории (или импортируйте из предыдущих сообщений).
Основной сценарий:

Логин как админ → POST /api/login (email: admin@example.com)
Создать комнату → POST /api/resources (с токеном админа)
Логин как обычный пользователь
Создать бронирование → POST /api/bookings (указать resource_id и время)
Повторить то же время → 409 Conflict ("Время уже занято")
Посмотреть свои бронирования → GET /api/bookings
Отменить бронирование → DELETE /api/bookings/{id}
